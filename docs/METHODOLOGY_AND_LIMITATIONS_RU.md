# Методология, ошибки и пределы применимости

## Источник идеи

Джон Дж. Мэрфи, *Технический анализ фьючерсных рынков: теория и практика*, раздел «Недельное правило». Мэрфи описывает правило Ричарда Дончиана: разворот позиции при пробое максимума/минимума предыдущих четырёх полных недель. В книге также обсуждаются отдельные, более короткие правила выхода (1–2 недели). Мы **не тестировали их как часть этой замороженной версии**.

## Три разных определения

1. **Основная версия:** сравнение дневного закрытия с экстремумом **20 предшествующих торговых закрытий**; решение после завершения дня; позиция на следующий день. Эта версия не равна приказу по ценам HIGH/LOW из книги.
2. **Устойчивость:** экстремум закрытий предшествующих **четырёх завершённых недель**, исключая текущую неделю.
3. **OHLC-диагностика:** пробой предыдущих четырёх завершённых недель по HIGH/LOW, но только ES, GC, TY; если дневная свеча пересекла обе стороны, событие считается неоднозначным и позиция сохраняется. Обновление позиции лишь со следующего дня, поэтому это не исполнение стоп-заявки по цене пробоя.

## Портфель и издержки

- 84 разных фьючерсных ряда с неполным покрытием по эпохам; исторические непрерывные цены, USD excess returns и модельные volume-based costs из версии `trendfollowing==1.3.1`.
- Веса: прогнозируемая 60-дневная EWMA-волатильность с лагом один день, индивидуальная целевая волатильность 40%, затем равномерное деление на число доступных инструментов.
- Валовая экспозиция не ограничена 1x; в 2010+ средняя валовая экспозиция около **8.3x**, не подходит для простого розничного счёта.
- Движение позиции по close t применяется к return t+1; нет входа задним числом.
- Проверены расходы 0x/1x/2x/3x, где 1x означает **модельную таблицу расходов источника**, а не доказанные реальные комиссии конкретного трейдера.
- Главный критерий исследования — период 2010–2026-07, без дальнейшего подбора окон пробоя.

## Границы вывода

- Исторический бэктест **не является** фактическим экспериментом с реальными ордерами, стаканом и маржой.
- Нельзя говорить, будто **буквально правило Дончиана из книги** было опровергнуто на 84 рынках. Для этого потребовалась бы полная OHLC/тик-история и модель ордеров; основной широкий тест использует закрытия.
- Нельзя считать все 84 актива доступными на протяжении всей истории; меняется состав и ликвидность.
- Результат «чистая годовая арифметическая доходность 0.09%» не тождественен CAGR −0.58%. Это разные метрики, обе должны быть показаны.
- Использование settlement/benchmark вместо реальных ордеров и frozen volume-cost schedule — модельные допущения.
- Контроль TSMOM взят из независимой ветки QR2; он не пересчитывается автоматически при запуске одного лишь этого репозитория. Архивный CSV с его итогами включён.
- Нельзя утверждать, что трендовые системы перестали работать: проверена конкретная конструкция канала, портфеля и расходов.

## Исследовательские ловушки и техническая честность

- **Несовпадение теста с литературным правилом:** 20-дневные экстремумы закрытий — только прокси, поэтому отчёт всегда отделяет primary от OHLC-диагностики.
- **Высокая оборачиваемость:** ~153.3×/год в главной версии после 2009, модельный cost drag 3.56 п.п./год. Валовой Sharpe 0.314 недостаточен для сильного вывода и до расходов.
- **Концентрационный тест в исходном коде:** если сумма годовых доходностей 2010+ отрицательна, `best_year_share_of_positive_sum = NaN` и исходный булевый gate считает этот пункт формально пройденным. Это некорректная диагностическая трактовка; при отрицательном результате концентрационный критерий должен называться «неприменимо», а не «PASS». ФИНАЛЬНЫЙ ВЕРДИКТ НЕ МЕНЯЕТСЯ: остальные статистические/экономические условия провалены. Исходный скрипт сохранён без ретуши.
- **Неопределённость:** bootstrap 12-месячными блоками даёт 95% интервал примерно [−4.32%; +4.78%] для арифметической годовой оценки в 2010+, то есть результат статистически неотличим от нуля.
- **Отсутствие отдельной новой OOS-выборки для буквального OHLC-правила:** её диагностические результаты не позволяют на основании трёх рынков утверждать что-либо универсальное.
- **Нельзя "спасать" замороженный тест подбором срока пробоя/переобучением на современном участке**. Новая версия требует нового протокола и независимой истории.

## На что смотреть независимому проверяющему

1. Запустить `scripts/fetch_data.py`, убедиться в совпадении SHA256 wheel.
2. Запустить `run_research.py`, сравнить основные показатели `scripts/verify_reproduction.py`.
3. Просмотреть отличия 20D close vs literal completed-week close vs HIGH/LOW test.
4. Самостоятельно проверить логику `shift(1)`, позиционирования и списания costs.
5. При необходимости собрать независимый тест на настоящих дневных HIGH/LOW 84 рынков — это **новое исследование**, не часть закрытого v0.1.
